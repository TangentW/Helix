# 能力与限制

[English](Capabilities-and-Limits.md)

Helix 有意采用 fail-closed 策略。“Swift 编译器接受这个文件”不等于“字节码后端支持这个语法”，“编译器能为声明生成 SIL”也不等于“当前 HLBC Lowerer 与 Shell capability surface 支持它”。本文给出当前实际边界。

## 生产 HLBC 1.0 的 Swift 子集

### 已实现

- `Bool`、有/无符号定宽整数、`Float`、`Double` 与 64 位 Apple 平台的 `CGFloat`，包括已声明的算术、位运算、比较、移位和数值转换规则。完全具体化的标量 `min`/`max` 与有符号数值 `abs` 会保留 Swift 的操作数顺序、溢出、正负零和 NaN 语义。HLBC 常量和 HLVM 值按目标位宽原样保留 bits：可表示完整 `UInt64` 值域，binary32 也不会先转成 binary64 存储，因此 infinity、正负零、NaN payload 与 signaling 状态都能穿过 canonical 编码和强类型 Bridge 往返。常用具体标量标准库 API 统一按“操作 + 现场值类型”lowering，而不是按 SDK receiver 加特例。定宽整数覆盖 `min`/`max`、`bitWidth`、`isSigned`、`magnitude`、置位/前导零/尾随零计数、`byteSwapped`、`bigEndian`/`littleEndian`、`signum()`、clamping/truncating 转换、`isMultiple(of:)`、`quotientAndRemainder(dividingBy:)`、全宽乘除和五种 reporting-overflow 运算。`Float`/`Double` 覆盖常用常量、bit-pattern 往返、exponent/significand 分解属性、分类判断、`magnitude`、`squareRoot()`、`ulp`、`nextUp`、`binade`、`significand`、`sign`、全部 rounding 规则、IEEE/截断余数、融合 `addingProduct`/`addProduct`、total ordering，以及四种感知 NaN 和正负零的 min/max；其常见 mutating 形式归一到相同的强类型操作。除零、无法表示的全宽商、有符号最小值除以负一、正负零、subnormal 与 signaling NaN 都保留 Swift 行为；对零未定义的底层 count builtin 会明确拒绝，不做猜测。
- `Bool.toggle()` 与全局 `swap` 共用一条类型驱动的值修改路径。swap 支持普通、projection、frame 或可变 closure cell 中可表示且可复制的标量、文本、Optional、Tuple 与补丁内 aggregate；重叠 storage 会被拒绝，两次读取都先于任一写入。两者都不增加 API 专属 opcode 或 NativeImport。
- `String`、`Character` 与 `Substring` 使用显式逻辑文本合同，不导入标准库私有布局。表示层 `Character` 在每个 producer 或 Shell 边界都会验证为恰好一个扩展字素簇；`Substring` 归一为 Character 序列，不保留私有 slice storage 或 index identity。已支持字面量、相等/排序、拼接、String 的 Character/String append、Substring 的 Character append，以及二者对有限 Character Sequence 的 `append(contentsOf:)`/`+=`、标量和文本插值、重复与常见 String 构造、Unicode `uppercased`/`lowercased`、count/empty、prefix/suffix/contains、String/Substring 转换、Character 序列构造、String 序列 joining，以及按扩展字素簇执行的 `removeFirst`/`removeLast`（含计数形式）、`popLast`、清空与容量提示。这些变更与 Array-backed 值共用一个可表示 `RangeReplaceableCollection` 计划，不增加文本专用字节码。直接 Character/String suffix 不会拆分已有 String，其他可表示 Character Sequence 只物化并 join 一次。可失败的标量构造另覆盖 String 到 `Bool`、String/Substring 到全部可表示有/无符号定宽整数（十进制或运行时 radix），以及 String/Substring 到 `Float`/`Double`；整数 `String(_:radix:uppercase:)` 覆盖同一个完整整数族。两条按目标类型驱动的 HLBC 操作服务全部这些组合；Verifier 会拒绝不匹配的标量/radix shape，超出 `2...36` 的 radix 会把 Swift precondition 保留成受控 trap，不引入泛型标准库 NativeImport 或逐位宽操作。String 直接执行 `count`/`isEmpty`；需要 element 的 `first`/`last`、变换、关系、`Array(sequence)`、`reversed`、基于数量的 subsequence 与 split 会经验证归一为 Character Array，再进入现有有限 Sequence cursor、adapter 与 split 状态。嵌套可表示 Character 序列也可 flatten 后重建为 String。可变大小文本操作会预扣确定性的 UTF-8 工作量与输出存储。
- 上述字面量与相等/排序能力指 String 和 Character；Substring 当前通过归一的 Collection 遍历、转换与 Shell Bridge 使用，不声称尚未实现的独立 StringProtocol 比较入口。
- Tuple、`Void` 与 `Optional`，包括 `if let`、`guard let`、`??` 和 `try?` 产生的普通控制流，也包括 Dictionary semantic SIL 产生的地址型 Optional projection。显式 `.some`/`.none` 分支与 canonical SIL 的“单个 case + `default`”穷尽式写法会归一到同一个语义 case plan；`default` edge 不会凭空生成未绑定的 payload 参数，被丢弃的线性 payload 只释放一次。Optional case 事实会沿 Tuple 与补丁内 struct 的字段路径精确追踪：已证明的 projected payload take 只消费对应字段，兄弟字段或 caller-owned storage 不能借用该证明；确定式与条件式 projected cleanup 也会保留独立初始化的兄弟字段。脱离父存储的 Optional payload address 会按物理消费者而非 opcode 拼写分类：只读 load 保留父值，消费型 load 与 `@in` 会 take，store 或 `@inout` 修改会重建嵌套 Tuple/补丁内 struct 路径后写回；同一 payload 混用破坏性消费与修改会被拒绝。frame/runtime-backed `inout` scope 可以跨 throwing same-image call，并在 normal/error 两条 continuation 上对称关闭。非 throwing 的 compiler-only `inout` 调用还可使用经过验证的临时 address storage，并拒绝重叠 projection；需要在两条 continuation 上重建写回的 throwing compiler-only projection 仍会 fail closed。声明摘要中的 `T?`、`T!`、`[T]`、`[K: V]` 与冗余分组括号会递归归一为同一套强类型表示，也适用于补丁内 stored field。
- 对可表示 payload 支持直接 Optional 强制解包与 `unsafelyUnwrapped`；nil 解包保留专用且经过验证的 trap reason。没有 payload 的运行时 `nil` 会从已验证的静态上下文获得 `T`，并统一覆盖嵌套 Tuple、collection builder、mutation/sort/split state、Dictionary key/value 与 VM equality。
- captured frontend 产生的源码级不可恢复失败会成为显式、受验证的控制流，覆盖 `precondition`、`preconditionFailure`、`fatalError`、当前构建配置下生效的 `assert`/`assertionFailure`，以及 `try!` 的错误边。当前 frontend 的静态诊断变体复用已有 trap terminator，动态 String 与可表示 Error detail 共用一条 `source_failure` terminator；消息 autoclosure 保留源码求值时机，源码位置来自 HLBC source map，也不会把 Swift runtime failure symbol 暴露为 NativeImport。
- Array 支持值语义与相等、单元素 append、`+`、`+=`、`append(contentsOf:)`、单元素与 contents 插入、`replaceSubrange`、按位置/首尾/范围删除（包括计数删除）、`removeAll(keepingCapacity:)`、`reverse()`、`removeAll(where:)`、`swapAt`、`reserveCapacity`、`first`/`last`、`firstIndex(of:)`/`lastIndex(of:)`、`min`/`max`、`elementsEqual`、`starts(with:)`、`lexicographicallyPrecedes`、`startIndex`/`endIndex`、`distance(from:to:)`、索引移动与有限偏移、`indices`、`popLast`、迭代、安全下标和返回新值的更新。单元素 append、`append(contentsOf:)` 与 `+=` 同样适用于归一的 ArraySlice destination；contents source 可以是规范化源码级 Element 身份与物理 shape 均匹配的任意受支持有限可表示 Sequence，包括 managed Array/ArraySlice/Set/Dictionary storage、String/Substring Character Sequence 与受支持的具体 progression。其余结构编辑支持所有可表示且可复制的 element 与类型匹配的 Array-backed 来源；它们统一降低到经过验证的单元素 append、半开区间替换、adapter 与通用 mutation 原语，因此边界、溢出、ownership 和分配前复制计费不依赖某个 element 或 SDK 类型。具体 `+=` metatype、包含 Tuple label 和被 HLBC 擦除差异的源码级 Element 身份、物理 shape 与线性 ownership 都会在变更前验证。容量变更提示受支持，但读取 `Array.capacity` 会明确拒绝，因为 VM 物理存储容量并不等同于 Swift Array 语义；`randomElement()` 也会在随机性及其可观察 policy 被显式表示前 fail closed。符合类型约束的 Dictionary 支持构建、相等、查找、下标赋值、惰性的 `subscript(_:default:)` 查找与 scoped 修改、`updateValue(_:forKey:)`、`removeValue(forKey:)`、`removeAll(keepingCapacity:)`、`keys`/`values` 序列物化、`init(uniqueKeysWithValues:)`、`reserveCapacity` 与迭代。插入、替换和删除共用一个强类型 Optional-update 原语，同时返回旧值和更新后的 Dictionary；key/value view 共用一个按所选 element 类型参数化的投影原语。默认查找只在缺键时调用 autoclosure；它的 `_modify` 与 Array element `_modify` 共用 scoped frame storage，并在 `end_apply`、`abort_apply` 两条出口都回写，因此嵌套和可抛错 inout 修改不需要集合 API 专用字节码。两条路径都会在复制前预扣遍历工作量和输出存储。可表示 element/key/value 还支持泛型 `Array()`/`Dictionary()` 空构造。Array、Dictionary、Set 共用直接的 `count`、`isEmpty`、`first` 查询，Array 另通过已表示的双向存储支持 `last`；已经归一的 Array-backed view 使用同一套查询。相等语义统一递归覆盖 Bool、定宽整数、浮点、String，以及受支持的 Optional、Array、Dictionary 与 Set；Dictionary/Set 按无序值比较，集合相等保留 Swift 的共享存储快速路径，Float/Double 则保留 Swift 的 NaN 与正负零行为。自然排序仍只允许 VM 无需执行用户 witness 就能比较的整数、浮点与 String element；非可变 `sorted()` 可接受 element 满足该约束的任意可表示 managed Collection 或受支持有限 progression，而可变 `sort()` 支持具有可表示整数索引的 Array-backed mutable Collection。Comparator 驱动的 `sorted(by:)` 通过普通已验证 closure ABI 支持任意可表示且可复制的 Array、Set、Dictionary element 与受支持有限 progression，可变 `sort(by:)` 使用同一 Array-backed 整数索引边界。Set 支持空值、字面量、Array/Set/受支持有限 Sequence 构造，`count`、`isEmpty`、`first`、`contains`、`insert`、`update`、`remove`、`popFirst`、`removeFirst`、`removeAll`、容量提示、迭代，union/intersection/subtraction/symmetric-difference 系列，以及常见 equality/subset/superset/disjoint 关系。Set 的顺序不会参与相等性；HLVM 只在同一个值内保留确定的迭代顺序，以保证执行和诊断可复现。Dictionary key 与 Set element 的 Hashable domain 使用同一个递归 VM 值类型族。下载代码不能执行任意用户 hashing/equality，因此自定义 `Hashable` 或 equality witness 会 fail closed。完全具体的 `map`、`flatMap`、`compactMap`、`reduce`、`reduce(into:_:)`、`forEach`、`first(where:)`、`contains(where:)`、`allSatisfy`、`count(where:)` 与 comparator 驱动的 `min(by:)`/`max(by:)` 会在可表示的 String、Array、Dictionary、Set 上复用同一套已验证 closure 遍历；Dictionary element 使用原生 `(key: Key, value: Value)` 元组形状。String 与三种 stored container 都支持保留逻辑容器类型的 `filter`，Dictionary 另支持 `mapValues` 与 `compactMapValues`，其专用 key/value callback ABI 从同一元组遍历投影。自然 `min()`/`max()`、等值 `contains(_:)` 与 `elementsEqual`/`starts(with:)`/`lexicographicallyPrecedes` 也接受满足对应 VM-defined Comparable/Equatable 约束的 managed Collection 与受支持有限 progression；关系两端只要 element 形状一致，就可以使用不同来源类型。这些只消费 element 的操作直接流式遍历同一个 cursor，不物化中间 Array。反向 `last(where:)` 支持 String 与 Array-backed 来源；具有可表示整数索引的 Array-backed 来源会为 `firstIndex(where:)`/`lastIndex(where:)`、可变排序、`reverse()`、`removeAll(where:)` 和 `partition(by:)` 保留逻辑基址。String 与 Array-backed 来源支持 `prefix(while:)` 和 Collection `drop(while:)`。产生新结果的变体共用 invocation-local 线性元素缓冲，并按结果类型收尾为 String、Array、Dictionary 或 Set，避免反复 copy-on-write 编辑。其中 `last` 搜索会从尾部调用 predicate，comparator selection 则保留 Swift 的参数顺序和“tie 取最早元素”行为。Comparator 排序使用有界且稳定的归并状态机。partition 保留 Swift 的 low/high 双向 predicate 顺序与原地交换排列；`removeAll(where:)` 按源顺序访问，使用同一套通用可变快照做半稳定压缩，再一次性删除后缀。可变排序只在所有 comparator 成功后写回；partition 与 predicate 删除则会在 predicate 抛错时写回此前已经完成的交换，callback 已产生的其他副作用同样可见。Array-backed Collection 与 String 的 `split` 同时支持 `separator:maxSplits:omittingEmptySubsequences:`（element 具备 VM 递归定义的 Equatable 语义）和可抛错的 `whereSeparator:`（任意可表示且可复制的 element）。两者共用带 kind 校验的线性 range 状态：被省略的空段不消耗 `maxSplits`，达到上限后不再调用 predicate，负数上限会在任何 callback 前 trap，抛错边会销毁全部临时 ownership。返回的 subsequence 保留元素顺序；Array-backed 整数索引来源还会保留每个片段的逻辑下界。String subsequence 使用表示层 Substring Character Array，不保留 `String.Index`。具体来源可归一为 Array-backed 序列时，也支持 Sequence `prefix(while:)`；惰性的 Sequence `drop(while:)` 仍会被拒绝，因为立即物化会改变 predicate 副作用的发生时机。`enumerated()`、`Array(sequence)`、异构 `zip` 与 `reversed()` 通过同一受验证物化路径接受 String、managed Array、Set、Dictionary 与有限 progression 来源；String 与 Array-backed adapter 另外支持基于数量的 `dropFirst`/`dropLast`/`prefix`/`suffix`、整数 index prefix/suffix、`Range<Int>`/`ClosedRange<Int>` 与单侧范围 slice、`joined()`、`joined(separator:)`、迭代，以及 base 已经可归一时组合出的 `Slice<Base>`。`repeatElement` 与 `Array(repeating:count:)` 继续复用同一 Array builder。嵌套可表示 Character 序列可以 flatten 并重建为 String。`ArraySlice` 与递归 Array-backed 的 `Slice` 会在嵌套 view、边界、移动、距离、`indices`、元素/范围下标、搜索、predicate subsequence、split、排序和受支持变异之间携带逻辑基址；`Array(sequence)` 会有意把新 Array 重置为零。具有不透明私有索引的 Collection 仍会 fail closed，不会被近似成整数 offset。payload 可表示为补丁内局部值时，`Optional.map`/`flatMap` 与具体 `Result.map`/`mapError`/`flatMap`/`flatMapError` 统一使用带显式 payload ownership 的选定 case 变换；`Result.get()` 会把 success/failure 投影到经过验证的 normal/error 边。局部 `Result` 当前不能嵌入 native handle。
- 可表示的整数索引 Collection 还统一支持变异式 `formIndex(after:)`、`formIndex(before:)`、`formIndex(_:offsetBy:)` 与受限偏移；失败的受限变体把 index 停在 limit 并返回 `false`，溢出、越界和 logical base 均保留 Swift 语义。Repeated 与 Array 共用零基 Array-backed 模型，包括 start/end、移动、距离、indices、安全下标与泛型 associated-index 的间接结果 ABI；ArraySlice 与递归 Array-backed Slice 继续保留逻辑基址。Dictionary/Set 的 `minimumCapacity` 构造与空构造共用强类型计划，容量本身在当前表示层不可观察，但负数仍在任何构造前以 Swift precondition trap。Array、Dictionary、Set 与已归一 Collection 的直接 `underestimatedCount` 返回精确值；Zip2Sequence 会递归保留来源的 Sequence-witness 估算规则，遇到 enumerated 或 flattened/joined 来源时返回 `0`，不能用已经物化结果的精确长度替代。
- `Result(catching:)` 只调用一次同步 throwing closure，并由受验证的 normal/error continuation 构造与其他具体 `Result` API 相同的局部 enum；它不通过 NativeImport 调用 Swift 泛型实现，也不增加 API 专属 opcode。本地名义聚合可承载受管的 `Error` existential；具体局部负载仍受 capability 约束，并在 existential 构造时和 VM 边界执行深度与 fuel 检查。局部 `Result` 仍不能嵌入 native handle。
- String 的 element consumer 会先经过一次受验证的 Character Array 物化，再进入共享 cursor；无需中间 Array 的直接 streaming 适用于已经由 managed Collection storage 或 progression cursor 表示的来源。
- 泛型间接结果可通过与普通 store 共用的强类型 compiler-address sink，初始化原始 Array 字面量 storage 的整个 element 或其中一个 Tuple 字段。
- `Sequence.prefix(while:)` 的直接 Array 结果形式还接受所有可表示的有限 specialization，包括受支持的 progression；它不要求来源能归一为 Array-backed Collection。惰性 `Sequence.drop(while:)` 仍会被拒绝，因为立即物化会改变 predicate 副作用的发生时机。
- Dictionary 还支持 `init(_:uniquingKeysWith:)`、Dictionary 与可表示 Sequence 两种 `merging`/`merge`，以及可表示 managed Array/Set/Dictionary 来源和已归一 Array-backed adapter 上的 `init(grouping:by:)`。grouping 通过融合后的 Array-valued 累积 append 线性增长 bucket，不会反复复制整组。combine callback 只在重复 key 上调用；首个等价 key 的 identity、插入位置、来源遍历顺序和 `rethrows` 都会保留。可变 `merge` 抛错时保留此前已成功的前缀修改，返回新值的构造则销毁部分结果。
- frontend 生成的 `_arrayForceCast` 与 `_dictionaryUpCast` 只有在原始类型仅有 Tuple label 差异、且递归归一后的完整来源/目标 VM 类型也完全相同时才会被接受，用于覆盖直接或嵌套容器中的 label 擦除。仅有相同底层表示并不充分；真正改变 element、key、value 或 reference type 的转换仍会被拒绝。
- 结构化分支、循环、switch、调用、递归、显式业务错误边和带 payload 的局部 Error 值。真实 frontend 语料已覆盖三元、`if`、`switch` 表达式，多 Optional binding，`repeat-while`、`for where`、带标签的 `break`/`continue`、Tuple 与 Optional 模式匹配、`if case`、`guard case`、`for case`、`while let`、`while case`、`fallthrough`、提前返回，以及循环与返回清理路径上的 `defer`。直接调用的局部函数、带捕获的 closure 值、作为 transform 传入的局部函数，以及具体 operator function reference 也统一走普通的受验证函数与 closure 路径。
- 所有已支持有/无符号定宽整数的 `Range`/`ClosedRange` `for` 循环，以及这些整数、`Float`、`Double` 和 64 位 `CGFloat` 的 `stride(from:to:by:)`、`stride(from:through:by:)`。`Range.contains`/`ClosedRange.contains` 还支持已支持整数、浮点和 String 边界。Lowerer 统一生成以 Optional 为 cursor 的强类型 HLBC progression，不依赖标准库 Iterator ABI；下面列出的有限具体 Sequence 操作会复用这个 cursor，不增加 API 专属 opcode。零步长、非法区间边界保留 Swift trap，整数极值也不使用会碰撞的 sentinel。
- 有限具体整数 `Range`/`ClosedRange` 与受支持数值 stride 会复用 managed Collection 的正向高阶遍历，覆盖 `map`、`flatMap`、`filter`、`compactMap`、`reduce`、`reduce(into:_:)`、`forEach`、`first(where:)`、`contains(where:)`、`allSatisfy`、`count(where:)` 以及 comparator 驱动的 `min(by:)`/`max(by:)`；产生新容器的变换返回 Array，并保留相同的短路、抛错和可变捕获语义。它们还支持等值 `contains(_:)`、自然 `min()`/`max()`、与 managed Collection/另一个 progression 混合的 Sequence 关系、自然/comparator `sorted`、`Set(sequence)`，以及 sequence operand 已完全具体且有限的泛型 Set 代数。整数 Range/ClosedRange 的 `count`、`isEmpty`、`first`、`last` 是直接读取 bounds 的常数时间查询；count 覆盖 element 的完整位宽，并在基数超过 `Int.max` 时 trap。可表示 Comparable bounds 的 Range 也支持 `isEmpty`，但不会因此获得迭代能力。只消费 element 的操作保持短路或单 candidate 流式执行；排序与 Set 结果才通过统一强类型 builder 物化。`Array(sequence)`、`enumerated()`、`reversed()` 与异构 `zip` 同样只在结果需要存储或随机访问时物化 progression。反向 predicate 搜索、返回 index 的搜索、其他 index-sensitive Collection boundary/subsequence，以及把单侧 partial range 当作可能无限的 Sequence 来源，会在方向、index identity、复杂度或终止条件能够精确表示前继续 fail closed。
- 整数 Range/ClosedRange 的 `underestimatedCount` 与 `count` 共用精确 bounds 计算；StrideTo/StrideThrough 则通过同一个受 fuel 限制的 cursor 做精确 Sequence-witness 计数，只使用常数额外空间。半开定宽整数 Range 的计数式 `dropFirst`/`dropLast`/`prefix`/`suffix` 会在常数时间内移动并 clamp 一个强类型 bound，不把完整基数收窄到 Int，覆盖 Int/UInt 64 位极值；ClosedRange 的不透明 SubSequence index 仍不据此放宽。
- 可表示 Comparable bounds 的 `Range` 还支持 `overlaps`、`clamped(to:)` 与上下界访问；空区间永不 overlap，clamp 在相等时保留原始 bound，包括浮点 signed zero。它们与 `isEmpty`、`contains` 共用强类型 compare/select 与 progression storage 生命周期，不引入泛型 NativeImport 或逐 API opcode。
- `PartialRangeFrom`、`PartialRangeUpTo`、`PartialRangeThrough` 的 containment（包括 switch pattern 产生的 `RangeExpression.~=`）对可表示整数、浮点、String 与 Character bounds 共用一套强类型比较计划；动态无序浮点 bound 仍保留 Swift 构造 trap。具有可表示整数索引的 Array-backed Collection 以 `Range<Int>`、`ClosedRange<Int>` 或单侧 `Int` bound 下标时复用既有 range/suffix/prefix subsequence 操作并保留下界；全范围 `[...]` marker 则在可表示 Array-backed 或 String/Substring 来源通过既有物化边界归一后被消除。这些范围值只存在于 Compiler：不会序列化 Swift 泛型集合 ABI，不会把标准库方法注册为 NativeImport，也不会新增逐源码 API opcode。自定义 `Comparable` witness 与 `String.Index` 等私有 index identity 仍会 fail closed。
- 可在现有受监视文件中新加、且不导出到原生 ABI 的文件或 module scope 补丁内非递归 stored struct/enum；支持具体 `Result`、字段读取、enum switch、实例/静态计算 getter/setter 与受支持的 mutating helper。逗号分隔的 enum case（包括 labeled/unlabeled associated value 混合）按顶层边界解析，重复、空或畸形 case 摘要会 fail closed。嵌套声明保留完整 namespace identity。它们是仅属于当前 generation 的 VM 值，不是新加载的 Swift metadata。
- 新增普通函数、private 方法和计算属性会作为同一 image 的普通函数、getter 或 setter 被传递发现并编译，不要求它们预先出现在 Shell EntryIndex 中。patch-local `final class` 具有 HLVM 自己的引用 identity、字段 storage 和方法调用；纯 HLVM class 仍不能跨原生边界。
- 新增 `final` class 可以选择一个 HLXI 已冻结、`NSObject` 兼容的 reference superclass。Runtime 为每个不可变 image 注册 Objective-C host，使对象能以该 superclass（包括 `UIViewController` 或项目基类）的身份交给原生代码。当前 hosted profile 仅支持继承的无参初始化、无新增 stored property，以及无参或单个 `Bool` 参数的 `Void` override；原生侧不能识别补丁新增的 Swift 具体类型。
- 同步补丁内 `inout` 与 `mutating` helper，并受 Address、access、alias、ownership、同 frame/同 block 规则验证；其中包括编译器为捕获可变局部变量的 `defer` helper 生成的 `@inout_aliasable` / `@closureCapture $*T` 物理 convention。
- 捕获 copyable 可表示值的同步补丁内 closure，包括 nonthrowing 与 throwing 调用路径。可变局部值统一提升为与具体类型无关的 VM cell，可覆盖标量、String、Optional、Array、Dictionary、Set、Tuple、补丁内 struct、字段投影、嵌套捕获，以及 Swift 为 escaping closure 生成的 `{ var T }` box。字段敏感的“确定/可能初始化”分析还覆盖分支初始化、条件覆盖与清理，但不会把可能初始化的值当成可读值。它包括同 image helper 的 `@escaping` 参数、从同 image 函数把 closure 返回给调用者，以及 closure 再捕获另一个 closure。closure 还可作为 Optional、Tuple、Array、Dictionary、补丁内 struct/enum/class 字段、可变 closure 变量和高阶参数/返回值；capture list、递归 closure 变量、局部/绑定 method 引用、多 trailing closure 与 escaping autoclosure 都复用同一值模型。具体 closure ABI 会保留每个参数的 owned/borrowed/inout convention，包括受支持高阶操作中的 `@in_guaranteed` Optional、imported SDK reference value、普通 same-image closure 的 normal/throwing inout 调用，以及 `reduce(into:_:)` 使用的 scoped frame-owned mutation。可复制的线性捕获（例如 imported reference）只有在 closure body 以 borrowed capture ABI 接收时才会复制进 managed closure context；owned 与 inout 线性捕获仍会被拒绝。完全具体的 direct/indirect-result reabstraction thunk 会作为 image-local compiler-generated function 链接，只有被 partial apply 时才使用 closure-body role；仅被直接调用的 closure 与 `defer` helper 会保留物理 capture ABI，并作为 concrete specialization 链接，不会走 NativeImport。on-stack `partial_apply` 与 `withoutActuallyEscaping` 使用显式动态 scope identity：Verifier 证明 normal/throwing 的每条 CFG 路径都会关闭 scope，VM 会拒绝 scope 结束时仍存在于显式 storage，或仍可经后续语义用途到达的 closure；已经无后续用途的 SSA 物理别名不会被误报为逃逸。词法期 nonescaping closure 可以通过 managed-cell capture ABI 借用调用者的 `inout` address；address access 结束即使借用失效，静态验证与 VM 都要求先关闭 closure，escaping capture 则拒绝。其他普通 closure 值必须留在同一次固定 generation 的 HLVM invocation 内；只有下条精确 NativeImport callback 参数可以通过受管 handle 延长生命周期。返回与嵌套捕获由 `escaping-closure-values-1` 门禁，managed cell 由 `mutable-captures-1` 门禁。Compiler 生成且不再包含 archetype、metadata 或 witness 依赖的完全具体 specialization 可以直接使用；语义 SIL 中在同 image 的具体 `apply`、`try_apply` 或 `partial_apply` 调用点使用的源码泛型 helper 也会被单态化。不同参数列表获得确定性的 image identity，call binding 仍保留原 Swift symbol；递归、rethrows、高阶与 escaping function-value 形态共用同一路径。未解析参数、pack，以及仍需 metadata 或 witness dispatch 的 body 会明确失败。
- 安全的 `weak` 与 checked `unowned` capture list，以及被 closure 捕获的 weak 局部变量，会复用同一 managed-capture ABI。共享的不持有对象 handle 可以指向补丁内 class 或已冻结 identity 的 native reference：对象释放后 weak load 变为 `nil`，已失效的 checked-unowned load 则触发受控 VM trap。该 storage 及其创建、访问指令统一由 `non-owning-references-1` 门禁。
- NativeImport 的 callback 参数走一套精确且不依赖 framework 的生成式 bridge profile。typed AST 提供源码 closure 类型，canonical SIL 提供物理 `@noescape`/escaping 生命周期、Objective-C block reabstraction、ownership 与 global-actor 证据。当前接受直接或 Optional 的同步、nonthrowing、`Void` callback；callback 参数可递归使用普通 native bridge value 家族，但不能是 `inout`、高阶 closure 或 image-local value。nonescaping callback 只在当前原生调用期间有效；escaping callback 可以被该精确参数保留、超过原 VM invocation 的生命周期，并携带 generation lease 在之后重新进入原 image。在通用 `Sendable` 语义实现前，同一 Runtime Engine 会串行化所有 callback：允许同线程递归，进行中的 NativeImport 不能把 callback 跳到另一线程，不同线程的重叠 callback 会 fail closed。`UIView.performWithoutAnimation`、`UIView.animate`、`DispatchQueue.main.async` 与 `Timer.scheduledTimer` 都由这条通路覆盖，而不是逐 framework 适配。callback 旁被省略的源码默认参数会记录为经过检查的物理到逻辑投影，只有 SIL provenance 与 ownership 验证通过后才由生成的 Swift 调用按语言规则补上。
- 顶层无 suspension 的 `async`、`async throws` 和 `@MainActor async` entry。生成的精确 Swift wrapper 保留 ABI，HLVM 只执行已经证明不会挂起的 body。
- VM-owned `Any`、`is`、`as?`、`as!`。闭合的递归逻辑类型描述符会区分有意共用 HLBC storage 的源码类型，包括 `Int`/`Int64`、`UInt`/`UInt64`、`Double`/`CGFloat`、String/Character、Substring/Array 以及 Array/ArraySlice。Optional、Array、Dictionary、Set 与 Tuple 的递归转换会保留这些身份；ArraySlice 与补丁内 nominal value 支持精确动态身份。递归 Dictionary/Set 转换产生的 key/element 碰撞会以受控 VM trap 保留 Swift 的终止行为。v1 描述符最多允许 32 层嵌套 wrapper、64 个 tuple element，以及每个 tuple label 256 个 UTF-8 字节。Swift existential metadata、native object 和线性生命周期不会进入下载字节码。
- 完全具体的默认参数 generator。生产与开发编译器会把可达 `fA...` thunk 一起链接并纳入传递实现指纹；当前只承诺一个完整 module source set 内的 eligible 调用点。跨 module 的 public/package 默认值、非 eligible 调用点或仍需泛型 metadata 时要求完整构建。
- 所有新 Shell 会自动冻结原生 Swift 文本渲染能力：普通 `Swift.print`、`Swift.debugPrint`、`String(describing:)` 与 `String(reflecting:)`。两种 print 保留 variadic separator/terminator 语义；两个泛型 String initializer 会在 Compiler 证明源码动态类型可精确重建后，经固定的 `Any -> String` 适配层调用。共享 codec 支持递归的标量、文本、Optional、Array、Dictionary 与 Set，所有操作统一限制 64 KiB 输出；无需 App 手工配置 Catalog，也不引入泛型 metadata、witness table、新 opcode 或合同版本。
- 受管 Debug 会测量所有“已经冻结 imported native type”所属 module 的公开成员。捕获 toolchain 的 symbol graph 负责提名满足 minimum OS 的 API，同一 typed AST/canonical SIL 流程只冻结唯一且 Bridge-compatible 的 initializer、同步实例/静态 method 与可读/可写 property。这条通用路径覆盖 Swift 与 Objective-C 声明、Swift overlay/物理 alias、SDK actor 隔离，以及 Objective-C 实例方法被导入为逻辑 Swift `throws -> Void` 时已经证明的 canonical `NSError **` bridge；例如 `UIColor.black`、`UIColor.init(white:alpha:)`、`UIView.alpha`、`UIView.setNeedsLayout()`、`UIView.setAnimationsEnabled(_:)`、`URLCache.shared`、`Bundle.path(forResource:ofType:)` 与 `FileManager.removeItem(atPath:)`。生产 Shell 不会得到这组便利能力，它本身也不会引入新的 boundary type。
- 精确原生操作已冻结时的 Objective-C superclass dispatch 与 address-form Optional 控制流。同类型 receiver cast 只有在两端是同一 reference `TypeID` 时才作为 alias；Optional payload take 即使经过精确地址复制，也必须受 `.some` edge 支配。
- 调用同 image helper、eligible Shell entry 与目标 Shell 已经生成的精确 allowlisted NativeImport。发布基线已经使用、且 Typed AST 语义与 canonical SIL 物理 ABI 能够对齐的外部 API 可以自动冻结；当前覆盖 reference、raw enum、OptionSet、opaque copyable value、accessor、method、全局值/函数、简单 imported C value、Selector、upcast，以及已验证的 String/Array Objective-C bridge。

### 拒绝或有意未完成

- generic root，以及仍需要运行时 generic metadata、witness table、未解析/泛型 reabstraction 或动态 specialization 的执行。这也包括尚未归一为可表示 managed Collection、迭代语义不透明的自定义 `Sequence`；Helix 不会把它们经 NativeImport 转交给 Swift 标准库执行。
- 真正 suspension：`await`、continuation、Task、async callee、async closure、cancellation，以及跨 suspension ownership 或 generation lease。
- actor-isolated instance root、custom global actor 和任意 executor hop；上面的受限 `@MainActor async` leaf 是不同能力。
- closure 不能穿过 Shell Entry，也不能在上述精确 callback 参数 profile 之外穿过 NativeImport。普通 native value、native property、native result 与通用 boundary codec 都不能包含 closure；只有精确的 escaping callback 参数可以保留固定 handle。非 `Void` callback 结果、throwing/async callback ABI、`inout` callback 参数、高阶 callback 参数以及并发 `Sendable` 执行语义仍不支持；`unowned(unsafe)` 会因无法安全表达悬空引用而被拒绝，weak/unowned stored property 也尚未进入补丁内 nominal layout。调用者拥有的 `inout` 只能走上面经过验证的词法期 nonescaping 借用，escaping capture 仍会 fail closed。
- `String.Index`、基于 String index 的下标或修改、UTF-8/UTF-16/Unicode-scalar view、locale-sensitive 或 Foundation 文本 API，以及上文未列出的 Character 属性。它们会 fail closed，不会用整数 offset 或泛型 NativeImport 近似。超出上述定宽整数和浮点迭代面的 progression element type、把 Range/stride 值导出到 Shell 或 NativeImport 边界，以及函数局部 nominal type 声明也仍被拒绝。把不导出的补丁内 struct/enum 移到现有受监视文件的文件/module scope 后即可随补丁编译；只要它仍是 image 私有声明，就不要求重建 Shell。
- Dictionary key 或 Set element 的用户自定义 `Hashable` 语义仍会被拒绝。VM-owned `Any` 的闭合语法只允许递归且由 VM 定义 Hashable 语义的 key/element，因此不会隐式执行用户 witness。Swift Shell codec 会递归物化受支持的标量、文本、Optional、Array、Dictionary 与 Set，但仍拒绝 ArraySlice（类型擦除边界无法重建其非零公开索引基址）、Tuple、补丁内值、native object 与 closure；`Void` 也不能擦除，因为 HLVM 用“没有值”表示它。这些边界拒绝不会削弱同一 verified image 内 ArraySlice、Tuple 或补丁内值的内部精确身份。
- 任意新 Swift metadata、原生侧可识别的补丁具体 class、retroactive conformance，以及修改 Shell 已有类型的 layout、superclass 或 enum case。上面的 hosted Objective-C subclass 是冻结 superclass projection，不是动态生成任意 Swift metadata。
- Generic 或 `inout` Shell entry、noncopyable root、任意 borrowing/consuming ABI、typed-throws root、上述具体标准库操作之外的通用 `rethrows`，以及通用 unwind cleanup。
- 不受限 pointer、`unsafeBitCast`、任意 Objective-C selector/IMP、`dlopen`/`dlsym`、Mirror 字段修改与未知 builtin。
- 目标 Shell 中没有精确 `NativeImportID` 的原生调用，即使 App 中存在名字相似的 Swift 函数。生产补丁也不能给旧 Shell 新增 framework，或首次使用发布时未冻结的 SDK 操作。上面的受管 Debug 调色板之所以可用，正是因为正常 Debug Build 已经逐项冻结了这些 ID。

## 开发期 Live Reload 边界

默认 Live Reload 使用与生产相同的 canonical SIL、Verifier 与 HLVM 核心。开发路径改变的是 session、传输、生命周期与诊断策略，不会用下载的机器码兜底不受支持的字节码。

| 修改 | 当前结果 |
| --- | --- |
| 修改已索引的 global 函数体 | canonical SIL 位于文档子集内时支持 |
| 修改已索引的源码 class 实例方法体 | 支持；生成 TypeOps 会把精确 `self` 引用传入 HLVM |
| 修改 Shell 已有 struct/enum/actor 实例 root 或已有原生 static/class 方法 | 在 Shell value writeback、executor 与 native metatype ABI 实现前拒绝；这不限制 image-local 值类型的 accessor/helper |
| 从函数体调用已有 private/internal/public 声明 | 仅在解析为同 image 函数、eligible Shell Entry 或实际生成的精确 NativeImport 时支持 |
| 在受管 Debug body 中首次使用公开 SDK 成员 | 对唯一测得的同步 initializer、实例/静态 method 或可读/可写 property 支持，前提是所有 boundary type 已能由冻结 imported/Bridge 类型面表达，且声明满足 Shell minimum OS；带 closure 的 method 在所有 callback 都符合上述精确同步 `Void` profile 时同样支持，陌生 error bridge、async/generic callback 或声明、subscript 与不可表达签名需要完整构建 |
| 在现有源码文件新增普通顶层 helper、class private 实例方法或计算 accessor | 能从变化 root 到达、且具体签名与函数体落在 HLBC 子集内时支持；声明仅属于该 image |
| 普通直接递归 | 解析到同一不可变 HLBC image 内的函数 |
| 从源码有意调用上一代 | HLBC 不支持；应保存/激活一个恢复 generation |
| 使用受支持的局部 closure，或调用已经索引且带 `@escaping` closure 参数的同 image helper | 降入同一 image；closure 的返回和捕获只能发生在固定的 VM invocation 内 |
| 把完全静态只读 KeyPath 字面量用作 transform 或直接投影 | patch-local struct/class stored field、具体 getter 链（包括 generated accessor 能解析到精确 NativeImport 的 imported Objective-C property）以及静态 Optional chain/force/wrap component 可以组合成强类型零捕获函数；动态 KeyPath value、subscript index 等带捕获 component、无法证明的 component，以及 writable/reference-writable mutation 会被拒绝，因为 KeyPath 对象不是 HLBC Runtime value |
| 使用整数 `Range`/`ClosedRange` 迭代、数值 `stride` 或可表示 Range 查询 | `contains`、`overlaps`、`clamped(to:)`、bound projection 与上述具体迭代族会保留已验证的边界、空区间、signed-zero、方向、开闭端点、零步长 trap 与整数极值语义。progression 值仍只属于 image，不能穿过 Shell/NativeImport 边界 |
| 在受支持文本/Sequence API 中使用 `String`、`Character` 或 `Substring` | 通过经过验证的 grapheme 与归一 Character 序列表示支持，也可穿过 Shell Bridge 往返；`String.Index`、index-sensitive 修改、UTF view 与未列出的 Character/Foundation API 仍被拒绝 |
| 声明补丁内 struct 或 enum | 新增的不导出类型在文件/module scope 支持，包括 namespace 嵌套和受支持的计算 accessor；函数局部 nominal 会用精确类型诊断拒绝 |
| 声明补丁内 pure class | `final`、非泛型、只在同一 image 内使用时支持引用 identity、stored property、private/普通方法与计算 accessor；不能传给原生代码 |
| 声明继承现有项目类或系统类的 hosted class | superclass 必须已作为 `NSObject` 兼容 reference TypeOps 冻结；当前支持继承无参初始化、无新增 stored property及无参/Bool `Void` override，并以 superclass 身份交给 UIKit/原生 API |
| 新增无关声明、新原生 ABI 表面或新 Swift 文件 | 不会仅因声明存在而收集；source membership 或原生 ABI 变化需要完整构建 |
| 修改 stored property、签名、generic constraint、actor isolation、superclass、conformance 或 enum case | 拒绝，需要完整构建 |
| 修改 default argument 行为 | 完全具体的 generator 会与同一完整 module 内 eligible、已归档的调用点一起进入补丁；跨 module public/package 默认值、非 eligible 调用点或泛型 ABI 要求完整构建 |
| 修改 static/global initializer | 已经初始化的状态不会自动重放 |
| 新增 framework、package、macro/plugin 输入、bridging header 或 source membership | Dev Build Manifest 失效，需要完整构建 |
| 修改 storyboard、XIB、asset、strings、Core Data model、plist 或 entitlement | 不属于 Swift body Live Reload 路径 |

捕获的编译器上下文会保留原 access control，但可见性本身不是 Runtime capability。一个操作无法表示成 HLBC、也没有精确生成的 Entry/NativeImport 时，即便普通 Swift 允许访问，编译仍会失败。

Simulator 与设备使用同一套 HLBC 协议和 Runtime。仓库 Simulator E2E 已在同一 App 进程中应用修改并恢复 baseline；另有 128 代进程内 soak 验证 active/rollback、失败保存、generation 高水位与压缩保持有界。真实 iPhone 运行和长时间内存压力 soak 仍需补齐，才能列为经过验证。Native Dynamic Replacement 只保留为必须显式选择的内部实验，不是产品 fallback。

## UI 刷新边界

代码替换决定下一次函数调用的行为；UI invalidation 决定用户是否立即看到结果。

- Helix 会从已展示实例的运行时 class 自动还原 controller/view identity，并支持沿 superclass 匹配；UIKit 不需要 type registry。
- 常见 render 与 layout callback 会自动推导 constraint、layout 和 display invalidation，并保留原页面实例与内存状态。
- 初始化或业务自有刷新逻辑可以使用幂等 `LiveReload.Reloadable` hook；它不是普通接入前置条件。
- 重建 Controller 需要注册 Factory、route context、state capture/restore 和容器支持。
- SwiftUI 需要 `liveReloadBoundary`；`invalidateBody` 尽量保留 identity，`recreateSubtree` 会重置该 boundary 的局部状态。
- Helix 不会自动重放 `viewDidLoad`、`loadView`、initializer、observer 注册、subscription 或任意生命周期 callback。
- 没有安全目标或规则时，代码可以保持激活，但结果会是 `manualRefreshRequired`。

仓库 fixture 已证明无需注册的 UIKit controller/view 与 superclass 自动匹配、invalidation、状态保持、SwiftUI pulse 路由和 Debug Overlay 行为；它们不能认证所有 custom container、navigation/sheet 交互、observation graph 或长期副作用模式。

## 诊断边界

Canonical Swift debug metadata 会降低成经过 Verifier 检查的 HLBC source map，以 function、block 与 instruction offset 定位。生产 artifact 只保留无歧义的逻辑源码路径，不携带构建机绝对路径。反汇编可以标注这些位置；HLVM trap 会给出结构化 program counter，`HelixRuntime` 再补充固定的 generation、Shell entry、函数名与逻辑 Swift 位置后通知 observer。

这属于源码级故障归因，不等于替代 LLDB。HLBC 的交互式 breakpoint、单步、表达式求值与 time-travel debugging 尚未实现。不支持的语法仍会在 Mac 编译阶段用原逻辑源码位置明确失败。

## 安全与资源边界

生产与开发路径都会对未知版本、capability、目标、身份、重复记录、畸形容器和资源超限 fail closed。生产字节码具有 fuel、deadline、stack、register、调用深度、值形状、NativeImport 和内存计量。可变大小 VM 操作会原子预留已验证的最坏分配上界、退回未使用部分并保留实际计费；下载与 live transfer 会在分配和执行前进行有界检查。

开发期 Live Reload 会限制 artifact 字节与保留 generation。同步 Swift NativeImport 无法被硬抢占；只有具备 deadline 与 checkpoint 的 bounded/cooperative import 才适合进入生产 Catalog。真实设备尾延迟和内存压力仍是 Gate。

## 兼容性与分发

Swift Package 的平台下限为 macOS 14 与 iOS 15。补丁绑定一个 finalized Shell interface 与目标身份，不得猜测某个 App build 的包与另一个 build 兼容。

当前 Release Builder 允许 internal 与 enterprise HLBC policy。App Store 通道仍是 `policyBlocked`，受控 Native Release 后端尚未实现。平台政策、签名与组织审批独立于字节码引擎是否在技术上能运行。
